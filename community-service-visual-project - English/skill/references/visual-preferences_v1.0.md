# visual-preferences_v1.0.md

## 1. Purpose of This File

This file records the user's stable, long-term visual preferences.

It does not prescribe fixed colors, layouts, or compositions for every task. Instead, it defines:

- Which results better match the user's aesthetic;
- Which results should receive lower priority;
- How images, text, color, and components should form a unified visual language.

Specific solutions should still vary dynamically according to:

- The current task;
- Service scenario;
- Scenario references;
- User-uploaded images;
- Palette selection at Gate 01.2;
- Direction selection at Gate 02.

---

# 2. Core Aesthetic Keywords

Long-term preferences:

- Poster-first;
- Modern;
- Youthful;
- Comfortable;
- A tendency toward high saturation;
- Distinct hue jumps;
- Background-led;
- Editorial character;
- Graphic character;
- Community friendliness;
- Distributed information;
- Asymmetry;
- Interwoven images and text;
- Clear visual focus;
- Posters with an authorial voice rather than templated announcement pages.

---

# 3. Poster First

The result should read first as a poster, then as an information document.

Dislikes:

- Scientific research posters;
- Academic presentation pages;
- PowerPoint information slides;
- Word notices;
- Government affairs templates;
- A fixed three-part structure: top title + middle image + bottom explanation;
- All information packed into neat cards;
- Safe, clear results without visual personality.

Likes:

- An immediate key visual;
- Backgrounds or graphics that genuinely carry the composition;
- Headlines that participate in the image;
- Information hierarchy and variations in density;
- A visual structure that works even without reading the text.

---

# 4. Color Preferences

## 4.1 General Preferences

Prefer:

- Relatively high saturation;
- Clear hue differences;
- Accent colors with distinct hue jumps;
- Brightness without harshness;
- A modern, comfortable feel;
- Color participating in composition rather than merely coloring modules.

## 4.2 No Fixed Specific Colors

No longer bind the design to fixed combinations such as:

- Blue + yellow;
- Green + cream;
- Purple + acid green.

These may appear, but are not default templates.

Specific hues are determined jointly by:

- The current service scenario;
- Scenario references;
- Images;
- Task meaning;
- The user's Gate 01.2 selection.

## 4.3 Lower Priority

Deprioritize:

- Gray-blue + gray-green;
- Corporate PowerPoint blue;
- Large areas of light gray;
- All colors within a similar hue range;
- Safe, low-saturation palettes;
- Automatically becoming solemn and conservative because the subject is “public service.”

---

# 5. Background and Scene Image Preferences

## 5.1 With 1 Image

Prefer:

- Hero Background;
- Large-scale cropping;
- Full-bleed imagery;
- Headlines entering the background;
- Darkening / color tinting / reducing distracting colors where appropriate;
- Tonal restructuring to support layout.

Dislikes:

- A complete rectangular photograph neatly placed in the middle;
- An image functioning only as a content module.

## 5.2 With Multiple Images

Prefer:

- 1 hero image;
- Other images as support;
- Collage;
- Partial cropping;
- Filmstrips;
- Graphic masks;
- Unequal visual weighting across images.

Dislikes:

- Dividing images into equal cells;
- Even, photo-album-style arrangements.

## 5.3 Without Images

Accept and prefer Graphic Poster Mode by default:

- Large color blocks;
- Circles;
- Stars;
- Arrows;
- Lines;
- Paths;
- Icons;
- Simplified figures;
- Simplified buildings;
- Abstract settings;
- Large headlines.

Having no photographs does not mean reverting to an explanatory page on a plain background.

---

# 6. Information Volume Preferences

Information may be distributed.

Allow:

- Times in corners;
- Locations as labels;
- Service items as visual keywords;
- Secondary explanations at the edges;
- Information arranged along paths;
- A small number of compact information clusters.

Not all information needs to be:

- Equal in size;
- Equal in weight;
- Equally spaced;
- Fully spread out at the bottom.

If the user selects “key visual first” at Gate 01.2:

Secondary explanations may be further condensed, but essential facts must not be removed.

---

# 7. Font and Headline Preferences

## 7.1 Main Headlines

Main headlines may:

- Be very large;
- Press against edges;
- Span regions;
- Use unconventional line breaks;
- Stretch;
- Compress;
- Use offsets;
- Use outlines;
- Be converted to paths;
- Interact with images or color blocks.

## 7.2 Font Resources

Prioritize:

- Microsoft YaHei: body text and critical facts;
- Smiley Sans: main headlines and keywords;
- LXGW WenKai: warm, cultural, or festive supporting text;
- Noto Sans / Serif: only if already available in the current environment.

## 7.3 Dislikes

Dislikes:

- The same default font for all content;
- Undesigned system typography suddenly appearing in an artistic background;
- A headline that is merely ordinary bold text placed at the very top.

---

# 8. Component Integrity Preferences

This is an important new long-term preference in V1.0.

A visual component should maintain a unified visual language wherever possible.

For example, a speech bubble includes:

- Border;
- Fill color;
- Icon;
- Subheading;
- Body text.

If the subheading requires precision:

Prefer designing the entire bubble as a unified precise component, rather than:

- Generating the outer frame as an image;
- Suddenly overlaying a default Microsoft YaHei heading inside it.

## 8.1 Unacceptable Disconnection

Avoid:

- A generative hand-drawn border + bare system typography;
- An artistic label + ordinary Word-style body text;
- A highly designed main headline with supporting modules that look entirely like Office documents;
- Half a generative art poster and half a rigid PDF layout.

## 8.2 Preferred Integration

Likes:

- Designing fonts, borders, icons, and colors together within one component;
- Integrating precise text into the overall visual;
- Accurate critical facts that do not look pasted on separately;
- Generative visuals and precise typesetting serving the same design system.

---

# 9. Artistic Text Preferences

## 9.1 Text That Can Be Artistic

Suitable for artistic treatment:

- Main headlines;
- Subheadings;
- Slogans;
- Visual keywords;
- Very short labels.

## 9.2 Text That Must Be Precise

Prioritize precise typesetting for:

- Phone numbers;
- Times;
- Dates;
- Addresses;
- Organizations;
- Registration methods;
- QR code instructions;
- URLs.

## 9.3 Intermediate Types

Event highlights, service items, module titles, and similar content:

Decide according to the component.

If part of a graphic label / bubble / card:

Design it as a whole rather than simply adding a layer of ordinary system text.

---

# 10. Scenario Reference Preferences

`references/scenarios/` gives different service scenarios different visual tones.

Likes:

- Emergency services looking clearly different from children's activities;
- Health and free clinics looking clearly different from community music events;
- Designs that match the user's aesthetic without merely recoloring the same template.

Dislikes:

- Scenario categories changing only the colors;
- Every service category retaining the same layout;
- Treating scenario references as fixed templates.

---

# 11. Style Reference Pool Preferences

Keep 4–5 genuinely favorite posters in `references/style/`.

These may mix styles and do not need classification.

The Agent should extract:

- Shared visual tendencies;
- The user's preferred degree of boldness;
- Color energy;
- Headline scale;
- Image/text relationships;
- Background treatment;
- Graphic elements;
- Whitespace and rhythm.

Do not:

- Directly imitate one reference per proposal;
- Average multiple references into a conservative style;
- Copy distinctive illustrations or complete compositions.

---

# 12. Anti-Cardification

Avoid by default:

- Multiple equal-width rectangular cards;
- Top title bars;
- Middle image sections;
- Large bottom information bars;
- One box per piece of information;
- Overly rigid grids.

Containers may be used, but require a design rationale.

Prioritize:

- Nonrectangular color blocks;
- Circular labels;
- Stars;
- Paths;
- Arrows;
- Floating information;
- Edge alignment;
- Elements crossing layers;
- Image/text overlap;
- Density variation.

---

# 13. Gate 01 Palette Selection Principles

Long-term preferences do not determine the final palette on the user's behalf.

At Gate 01.2:

The Agent should dynamically propose 3–4 palette directions for the current task.

After the user selects:

That selection must serve as the formal basis.

If the user chooses “let the Agent decide”:

Combine:

- Scenario category;
- style;
- Images;
- visual-preferences;

to generate the final palette.

---

# 14. Final Evaluation Criteria

Results that better match the preferences usually have:

- An immediate memorable feature;
- A composition that works first;
- Color with personality;
- A background that genuinely participates in the design;
- Graphic headlines;
- Clear information hierarchy;
- Accurate critical facts;
- Precise text that preserves the overall visual;
- Components belonging to the same visual system;
- Poster structure and rhythm visible even without reading the text.

Least preferred results:

- Very safe;
- Very neat;
- Very complete information;
- But resembling an announcement page, PowerPoint slide, or explanatory PDF page.
