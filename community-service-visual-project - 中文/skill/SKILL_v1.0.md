# 社区服务信息主视觉设计 Skill — V1.0

## 1. 核心目标

将社区公共服务、健康提醒、行动指南、社区活动、服务地点、求助信息等内容转化为具有明确视觉主线、公共传播效率和设计感的海报。

本 Skill 优先保证：

- 信息准确，不虚构真实日期、地点、电话、机构、二维码指向等事实；
- 用户不需要预先理解项目目录，也不需要先手动准备 `brief.md`、`raw-task` 或 `input/images/`；
- 任务默认从对话输入开始；
- HUMAN GATE 01 不再输出长篇分析报告，而采用分阶段、动态分支的交互式问卷；
- 中英文案必须经过用户确认后才能进入视觉设计；
- 场景图片的数量、适配度和处理方式在图片真正上传后再判断；
- 配色由 Agent 基于任务与参考提出若干方向，再由用户在 Gate 01.2 中选择；
- HUMAN GATE 02 必须输出真正可比较的视觉草图，而不是只给文字说明；
- 最终优先输出 PNG；
- 视觉生成与精确文字排版按“组件完整性”融合，避免明显的“生成图 + 系统字体硬叠”割裂感。

# 2. 默认输入方式：Conversation First

## 2.1 对话输入为主

默认从用户当前对话中的自然语言任务开始，例如：

“帮我做一个社区宠物友好日海报，周六下午，面向居民家庭，中英文，4:5。”

Agent 应从这句话中提取已有信息，并只对缺失项继续询问。

## 2.2 文件输入改为可选

如果用户主动提供：

- Brief；
- Raw task；
- 图片；
- Logo；
- 二维码；
- 品牌规范；
- 参考海报；

则读取并合并到当前任务状态。

但不得要求普通用户先把这些内容放入固定文件夹才能开始工作。

## 2.3 工作区由 Agent 管理

Agent 可在项目内部维护：

`workspace/current-task/`

用于保存：

- 当前任务结构化信息；
- Gate 01 问卷结果；
- 已确认中英文案；
- 用户上传图片的任务引用；
- 场景与参考路由结果；
- 视觉方向记录；
- 最终参数。

用户一般不需要手动编辑这些文件。

# 4. 参考优先级

发生冲突时，优先级从高到低：

1. 用户当前回合明确要求；
2. HUMAN GATE 中已经批准的选择；
3. 用户提供的事实性内容；
4. `visual-preferences.md`；
5. 当前任务匹配到的 `references/scenarios/`；
6. `references/style/`；
7. Skill 默认规则。

不得为了模仿参考图覆盖用户已经确认的内容。

# 5. 场景参考路由

## 5.1 目的

根据任务语义自动选择更相关的社区服务视觉参考，使不同服务场景拥有不同的信息组织与视觉语气，而不是所有任务都套同一种排版。

## 5.2 基础分类

可按任务语义路由到：

- 健康义诊：义诊、健康咨询、体检、健康筛查等；
- 老年关怀：敬老、银龄、老人课堂、适老服务等；
- 儿童教育：亲子、儿童活动、绘本、儿童手作等；
- 政策宣传：政策解读、社保、反诈、公共办事指南等；
- 社区活动：市集、电影夜、音乐、旧物交换、邻里活动等；
- 环境保护：垃圾分类、旧物再利用、社区清洁、绿化等；
- 志愿服务：志愿招募、公益活动、邻里帮扶等；
- 应急服务：急救、消防、防灾、高温、暴雨、台风等；
- 通用：无法明确分类或跨多个场景时。

## 5.3 使用规则

- 每次优先读取当前任务最相关的场景参考；
- 场景参考用于启发信息组织、视觉语气、图形语言和版式节奏；
- 不固定“某场景必须使用某颜色”；
- 具体配色仍由 Gate 01.2 动态提出并由用户选择；
- 场景参考不得机械复制；
- 若任务跨两个类别，可读取两个类别，但避免一次性读取大量无关参考。

# 6. Style 参考池

`skill/references/style/` 是整体审美参考池。

建议用户保留 4–5 张真正喜欢的海报。

不要求：

- 每张图只负责一种功能；
- 按“配色 / 构图 / 字体”分类；
- 特殊命名；
- 为每张图写解释。

Agent 应综合提炼多张图反复出现的视觉倾向，例如：

- 背景主导程度；
- 标题尺度；
- 色彩活跃度；
- 非对称性；
- 图文重叠；
- 信息分散；
- 图形元素使用；
- 留白与密度关系。

不得为了融合所有参考而把风格平均成安全、保守的结果。

# 7. 三个 HUMAN GATE

三个 Gate 数量固定不变：

- HUMAN GATE 01：任务与视觉前提确认；
- HUMAN GATE 02：视觉方向选择；
- HUMAN GATE 03：最终成图审查。

其中 HUMAN GATE 01 内部分为：

- Gate 01.1A：基础事实与任务信息；
- Gate 01.1B：中英文案生成与确认；
- Gate 01.2：素材、配色与视觉策略确认。

Gate 01 尚未全部完成前，不得进入 Gate 02。

# 8. HUMAN GATE 01.1A — 基础事实问卷

## 8.1 目标

只收集“任务成立所必需的基础事实”，不在这一阶段讨论配色、风格化、图片适配度或视觉构图。

## 8.2 先自动盘点已有信息

Agent 先从当前对话和已提供资料中识别：

- 活动 / 服务名称；
- 主题；
- 目标受众；
- 时间；
- 地点；
- 主办 / 服务单位；
- 参与方式；
- 报名方式；
- 联系方式；
- 输出语言；
- 输出比例；
- 输出尺寸 / 分辨率；
- 是否计划提供社区场景图片；
- 其他必须事实。

已经明确的信息不得重复提问。

## 8.3 问题呈现形式

优先使用运行环境支持的原生可点击选择控件，例如：

- 单选按钮；
- 多选按钮；
- 下拉选项；
- 可点击卡片；
- 文本输入框；
- 文件上传控件。

如果当前运行环境没有原生可点击表单能力：

1. 优先生成轻量交互式 HTML 表单到 `workspace/current-task/gate01/`；
2. 若 HTML 表单也不可实际交互，则退回结构化文本问卷；
3. 不得伪装成“可点击按钮”但实际上不能点击。

## 8.4 问卷组织原则

- 同类型信息整合为一个题组；
- 一次呈现当前阶段真正需要的 3–6 个问题；
- 每个问题提供 2–4 个推荐选项；
- 必须保留“自定义 / 暂不展示 / 之后补充”等合理选项；
- 不要求用户阅读长篇报告；
- 用户回答后，根据答案动态生成下一组问题；
- Gate 01.1A 不要求一次收齐所有内容。

## 8.5 场景图片只问“数量意图”

这一阶段只确认：

- 不使用社区场景图；
- 准备上传 1 张；
- 准备上传多张；
- 尚未决定。

不得在图片尚未上传时提前询问：

- 是否压暗；
- 是否改色；
- 是否日夜转换；
- 是否适合任务；
- 是否拼贴；
- 是否风格化。

这些全部留到 Gate 01.2。

# 9. HUMAN GATE 01.1B — 中英文案生成与确认

## 9.1 触发条件

当 Gate 01.1A 已经获得足以生成文案的基础事实后，Agent 自动整理海报文案。

如果用户要求：

- 中文版：生成中文案；
- 英文版：生成英文案；
- 中英文各一版：分别生成中文案和英文案。

## 9.2 文案来源分层

### A. 用户提供的事实文案

必须忠实保留，例如：

- 时间；
- 地点；
- 电话；
- 机构名称；
- 报名方式；
- 地址；
- 真实服务项目。

不得擅自改变事实。

### B. Agent 建议的传播文案

可以主动生成：

- 主标题优化；
- 副标题；
- slogan；
- 活动亮点；
- 简短行动语；
- 温馨提示；
- 模块标题；
- 面向公众的简洁说明。

必须让用户知道这些属于 Agent 建议内容。

## 9.3 文案确认界面

优先用可点击表单 / 选择控件提供：

- 全部确认并继续；
- 中文需要修改；
- 英文需要修改；
- 两版都再精简一点；
- 两版都更有传播感一点；
- 保留事实信息，仅重写宣传文案；
- 我自己修改 / 补充。

若用户选择某一语言需要修改：

- 只继续处理该语言；
- 另一语言保持锁定；
- 修改后再次确认。

## 9.4 文案锁定规则

必须达到：

- 中文案已确认；
- 英文案已确认（若任务需要英文）；

之后才能结束 Gate 01.1。

视觉阶段不得擅自新增、删除或改写已经锁定的关键文案。

若为了版式需要压缩次要文案，必须在 Gate 01.2 或后续明确说明并获得用户同意。

# 10. HUMAN GATE 01.2 — 素材、配色与视觉策略确认

Gate 01.2 必须在文案确认后开始。

其问题必须根据用户实际提供的图片数量动态分支。

## 10.1 情况 A：0 张社区场景图

如果用户明确不上传，或最终没有可用社区场景图：

默认进入 Graphic Poster Mode。

优先使用：

- 大色块；
- 圆形；
- 星型；
- 箭头；
- 路径；
- ICON；
- 简化人物；
- 简化建筑；
- 抽象草地 / 街区；
- 大标题；
- 几何或手绘视觉元素。

不得因为没有照片就退回：

- 白底说明页；
- PPT 信息块；
- 普通公告栏。

### Gate 01.2 需要确认

- 纯图形海报 / 更克制的编辑海报 / 更活泼的插画图形路线；
- 信息密度；
- 动态配色方向；
- 是否加入场景性图形元素；
- 是否允许标题艺术化。

## 10.2 情况 B：1 张社区场景图

图片真正上传后，Agent 先分析：

- 是否符合任务语义；
- 时间 / 天气是否匹配；
- 主体是否适合作为背景；
- 是否有叠字空间；
- 是否存在视觉噪音；
- 是否适合作 Hero Image。

然后再生成 Gate 01.2 问卷。

### 允许用户确认的处理权限

可提供：

- 基本保持原图；
- 允许明暗 / 对比度调整；
- 允许色相 / 饱和度调整；
- 允许局部裁切 / 模糊 / 遮罩；
- 允许天气 / 日夜变化；
- 允许较明显风格化；
- 允许图形覆盖；
- 由 Agent 根据方向选择合理范围。

不得在用户未批准的情况下擅自进行大幅场景语义改变。

## 10.3 情况 C：多张社区场景图

Agent 先评估：

- 主题匹配；
- 构图；
- 清晰度；
- 留白；
- 叠字潜力；
- 视觉噪音；
- 色调一致性。

然后向用户推荐：

- 1 张 Hero Image；
- 0–2 张辅助图。

同时给出可点击选择：

- Hero + Supporting Images；
- 拼贴优先；
- 胶片 / 多窗格；
- 图形蒙版；
- 仅使用最优主图；
- 用户自行指定主图。

若采用多图，需要说明如何统一：

- 色温；
- 饱和度；
- 对比度；
- 裁切；
- 图形语言。

# 11. Gate 01.2 的动态配色选择

配色必须由用户选择，但选项由 Agent 根据当前任务动态生成。

不得固定每个任务都出现同一组颜色。

## 11.1 Agent 生成 3–4 个配色方向

每个方向应包含：

- 简短名称；
- 视觉气质；
- 主要色相关系；
- 为什么适合本任务；
- 是否适合当前场景图。

例如可能出现：

- 高饱和跳色；
- 现代舒适；
- 温暖亲和；
- 高对比警示；
- 清新自然；
- 夜间霓虹；
- 由 Agent 自动判断。

## 11.2 配色原则

总体偏好：

- 较高饱和；
- 色相有跳跃；
- 现代；
- 舒适；
- 避免科研蓝灰；
- 避免所有颜色都在相近色相内轻微变化。

但具体颜色必须由：

- 当前任务；
- 场景类别；
- 场景参考；
- style 参考；
- 上传图片；
- 用户选择

共同决定。

# 12. Gate 01 完成条件

Gate 01 只有在以下条件满足后才能结束：

- 基础事实足够；
- 必要事实的缺失项已经由用户决定“补充 / 不展示 / 后续提供”；
- 中文案已确认；
- 英文案已确认（若需要）；
- 场景图片策略已确认；
- 上传图片的语义适配与处理权限已确认；
- 配色方向已确认；
- 信息密度已确认；
- 视觉路线已确认；
- 必要语义元素已确认。

然后 Agent 将完整内部结果写入：

`workspace/current-task/task-spec.md`

对用户只显示精简确认摘要，不输出大段分析报告。

# 13. HUMAN GATE 02 — 可视化方向选择

## 13.1 必须生成实际视觉图

Gate 02 不得只给文字方向说明。

必须输出 3 张可比较的低保真或中保真视觉草图 PNG。

目的：

- 比较构图；
- 比较色彩；
- 比较图文关系；
- 比较场景图使用方式；
- 比较艺术感。

文字允许暂时简化，但不能用明显乱码或无意义占位。

## 13.2 三方向应根据图片数量变化

### 0 图任务

三个方向可从以下构图家族中选择：

- Typography-led；
- Graphic Composition；
- Editorial / Icon-led；
- Illustration-led。

至少一个方向必须完全依靠色块、图形、文字建立完整视觉，而不是纯色背景加信息框。

### 1 图任务

三个方向可从以下逻辑中选择：

- Hero Background；
- Hybrid Overlay；
- Image + Typography；
- Cropped Editorial。

不得三稿都只是“矩形照片 + 底部文字”。

### 多图任务

三个方向可从以下逻辑中选择：

- Hero + Supporting；
- Collage；
- Editorial Multi-window；
- Layered / Masked Composition。

不得只是调整图片排列顺序。

## 13.3 场景参考的作用

Gate 02 应读取匹配的 `references/scenarios/` 和总体 `style/`。

场景参考决定：

- 信息组织；
- 视觉语气；
- 版式倾向；
- 图形语言。

总体 style 决定：

- 用户长期喜欢的设计感；
- 色彩活跃度；
- 海报性；
- 背景与标题关系。

## 13.4 Gate 02 输出

输出：

- 方向 A PNG；
- 方向 B PNG；
- 方向 C PNG；
- 极短的差异说明。

然后停止，等待用户：

- 选择一个；
- 指定修改后选择；
- 全部否决并重做。

不得自动进入正式稿。

# 14. V1.0 渲染核心：组件级混合渲染

## 14.1 不再使用“页面一半生成图、一半 PDF 排字”的粗粒度分割

避免出现：

- 背景和气泡是生成式图像；
- 气泡里的标题突然变成默认微软雅黑；
- 生成图很艺术，但信息区像 Word 文档；
- 视觉系统被精确排版层切断。

## 14.2 采用 Component Integrity / 组件完整性原则

一个视觉组件应尽量由同一种视觉逻辑完成。

例如一个信息气泡包含：

- 外轮廓；
- 底色；
- 图标；
- 小标题；
- 正文。

如果其中的文字必须精确：

应优先将整个气泡组件在 SVG / HTML / Canvas 等精确排版系统中统一设计，而不是只把文字硬叠在生成式气泡上。

## 14.3 文本分为三类

### Type A — 关键事实文本

包括：

- 电话；
- 时间；
- 日期；
- 地址；
- 机构名称；
- 报名方式；
- 二维码说明；
- 网址。

要求：

- 100% 准确；
- 优先使用精确排版；
- 导出前逐字核对。

### Type B — 结构性信息文本

包括：

- 活动亮点；
- 参与方式；
- 温馨提示；
- 模块标题；
- 服务项目；
- 标签文字。

处理方式：

- 若属于一个卡片 / 气泡 / 标签组件，则组件整体统一渲染；
- 不应只把文字单独覆盖在风格不一致的生成式外框上。

### Type C — 表现性文本

包括：

- 主标题；
- 副标题；
- slogan；
- 强调短句；
- 视觉关键词。

允许：

- 得意黑等显示字体；
- SVG / Canvas 路径化；
- 描边；
- 变形；
- 拉伸；
- 错位；
- 图像生成艺术字。

但必须逐字检查准确性。

# 15. PDF 的角色重新定义

PDF 不再作为默认视觉生成中间层。

PDF 只在以下情况使用：

- 用户明确需要打印文件；
- 需要保留矢量文字与精确排版；
- 需要额外提交打印版；
- 需要验证关键事实文本的排版结果。

如果用户只要求 PNG：

最终必须输出 PNG。

不得因为使用 PDF / HTML / SVG 作为技术中间层，就把页面设计成“PDF 说明页”。

---

# 16. 字体策略

轻量字体策略：

- Microsoft YaHei / 微软雅黑：关键事实、正文、安全 fallback；
- Smiley Sans / 得意黑：主标题、短关键词；
- LXGW WenKai / 霞鹜文楷：可选温暖、文化、节庆类副标题；
- Noto Sans / Serif：仅当前环境已有时使用，不要求下载。

但字体选择必须服务“组件统一”。

若一个图形化组件需要精确文字：

应通过：

- 字体；
- 字重；
- 字间距；
- 描边；
- 色彩；
- 边框；
- 图标；
- 背景形状

共同设计该组件，避免默认系统字体直接裸叠。

---

# 17. HUMAN GATE 03 — 最终成图审查

在用户选择 Gate 02 方向后：

1. 建立正式视觉底层；
2. 完成组件级排版；
3. 校对关键事实文本；
4. 分别适配中文版和英文版；
5. 导出用户要求尺寸的 PNG；
6. 展示最终稿；
7. 进入 Gate 03。

Gate 03 必须允许用户检查：

- 文字准确性；
- 中文 / 英文语义；
- 主标题；
- 配色；
- 图片处理；
- 组件统一性；
- 信息密度；
- 是否有明显“生成图 + 系统字体硬叠”的割裂；
- 是否保持 Gate 02 选定方向。

未明确通过，不视为最终完成。

---

# 18. 双语版本规则

中英文必须：

- 语义对应；
- 不机械逐字翻译；
- 根据语言长度重新调整排版；
- 保持同一设计系统；
- 不要求像素级复制；
- 不得因为英文较长而随意删除重要信息。

若用户要求先确认文案：

必须在 Gate 01.1B 完成中英文确认，再进入视觉阶段。

---

# 19. 信息准确性规则

不得擅自编造：

- 日期；
- 时间；
- 地点；
- 电话；
- 机构；
- 人名；
- 二维码指向；
- 网址；
- 任何真实服务信息。

若缺失：

可让用户选择：

- 暂不展示；
- 后续补充；
- 删除该模块；
- 自定义填写。

不得在最终海报保留明显空白占位框。

---

# 20. Anti-Cardification

除非场景参考或任务本身明确需要卡片系统，否则默认避免：

- 顶部标题栏；
- 中部照片栏；
- 底部说明栏；
- 多个等宽卡片；
- 每项信息一个矩形框；
- PPT 式规则网格。

优先使用：

- 背景；
- 大标题；
- 图文重叠；
- 信息悬浮；
- 圆形 / 星形 / 箭头；
- 标签；
- 路径；
- 非矩形色块；
- 留白；
- 边缘排布；
- 视觉密度变化。

# 21. 最终 Verification

提交前必须检查：

## 21.1 First Focus Test
第一眼是否看到正确的主题与视觉焦点？

## 21.2 Poster vs Document Test
更像海报还是说明页？

## 21.3 Palette Test
配色是否符合用户在 Gate 01.2 的选择？

## 21.4 No-Box Test
去掉显著矩形框后，构图是否仍成立？

## 21.5 Scenario Fit Test
视觉语言是否符合当前服务场景，而不是每个任务都长得一样？

## 21.6 Image Strategy Test
0 / 1 / 多图策略是否与 Gate 01.2 决定一致？

## 21.7 Copy Lock Test
最终文案是否与 Gate 01.1B 确认版本一致？

## 21.8 Critical Text Test
电话、时间、地点、日期、机构等是否逐字准确？

## 21.9 Component Integrity Test
是否存在明显“生成式边框 + 默认系统字体硬叠”的割裂组件？

## 21.10 Bilingual Test
中英文是否语义对应且分别适配？

# 22. 最终目标

V1.0 的目标不是让用户学习目录结构，也不是让 Agent 输出一大段设计分析。

目标是：

- 用户用一句自然语言启动任务；
- Gate 01 通过真正低负担、可点击优先、动态分支的问卷逐步明确事实、文案、图片、配色与视觉策略；
- 场景参考库让不同服务场景拥有不同排版与视觉语气；
- Gate 02 直接让用户“看见”三种设计方向；
- 最终采用生成式视觉与组件级精确排版融合的方法；
- 在保证电话、时间、地点等事实准确的同时，保留主标题、气泡、图形、背景与整体版面的艺术感；
- 最终交付准确、完整、具有现代海报感的 PNG。
