# visual-preferences_v1.0.md

## 1. 文件定位

本文件记录用户长期稳定的视觉偏好。

它不规定每个任务必须使用固定颜色、固定版式或固定构图，而是规定：

- 什么样的结果更符合用户审美；
- 什么样的结果应被降低优先级；
- 图像、文字、色彩、组件应该如何形成统一视觉语言。

具体方案仍应根据：

- 当前任务；
- 服务场景；
- 场景参考；
- 用户上传图片；
- Gate 01.2 的配色选择；
- Gate 02 的方向选择

动态变化。

---

# 2. 核心审美关键词

长期偏好：

- Poster-first；
- 现代；
- 年轻；
- 舒适；
- 高饱和倾向；
- 色相跳跃；
- 背景主导；
- 编辑感；
- 图形感；
- 社区亲和；
- 信息分散；
- 非对称；
- 图文穿插；
- 视觉焦点明确；
- 有作者性的海报，而不是模板化公告页。

---

# 3. 海报优先

结果应首先像一张海报，再像一份信息说明。

不喜欢：

- 科研海报；
- 学术汇报页；
- PPT 信息页；
- Word 通知；
- 政务模板；
- 顶部标题 + 中间图片 + 底部说明的固定三段式；
- 所有信息都被装入整齐卡片；
- 安全、清晰，但没有视觉性格的结果。

喜欢：

- 一眼有主视觉；
- 背景或图形真正承担构图；
- 标题参与画面；
- 信息有层级、有密度变化；
- 视觉结构即使不看文字也成立。

---

# 4. 配色偏好

## 4.1 总体偏好

更偏好：

- 较高饱和度；
- 明确色相差；
- 有跳色；
- 明亮但不刺眼；
- 现代、舒适；
- 色彩参与构图，而不只是给模块上色。

## 4.2 不固定具体颜色

不再长期绑定固定组合，例如：

- 蓝 + 黄；
- 绿 + 奶白；
- 紫 + 酸性绿。

这些可以出现，但不作为默认模板。

具体色相由：

- 当前服务场景；
- 场景参考；
- 图片；
- 任务语义；
- Gate 01.2 用户选择

共同决定。

## 4.3 降低优先级

降低：

- 灰蓝 + 灰绿；
- 企业 PPT 蓝；
- 大面积浅灰；
- 所有颜色处于同一相近色相；
- 低饱和安全配色；
- 为了“公共服务”就自动变得严肃保守。

---

# 5. 背景与场景图偏好

## 5.1 有 1 张图

更偏好：

- Hero Background；
- 大面积裁切；
- 图像出血；
- 标题进入背景；
- 可压暗 / 偏色 / 降杂色；
- 可通过色调重构服务排版。

不喜欢：

- 一张完整矩形照片被规整放在中间；
- 图片只是内容模块。

## 5.2 有多张图

更偏好：

- 1 张 Hero；
- 其他作为辅助；
- 拼贴；
- 局部裁切；
- 胶片；
- 图形蒙版；
- 非等权多图。

不喜欢：

- 多张图平均分格；
- 相册式均匀排列。

## 5.3 没有图

默认接受并偏好 Graphic Poster Mode：

- 大色块；
- 圆；
- 星；
- 箭头；
- 线；
- 路径；
- 图标；
- 简化人物；
- 简化建筑；
- 抽象场地；
- 大标题。

没有照片不代表要退回纯色背景说明页。

---

# 6. 信息量偏好

允许信息分散。

允许：

- 时间放在角落；
- 地点成为标签；
- 服务项目变成视觉关键词；
- 次要说明边缘化；
- 信息沿路径排布；
- 使用少量小型信息簇。

不要求所有信息：

- 等大；
- 等权；
- 等距；
- 都在底部完整铺开。

如果用户在 Gate 01.2 选择“主视觉优先”：

可进一步压缩次要说明，但不得删除必须事实。

---

# 7. 字体与标题偏好

## 7.1 主标题

主标题可以：

- 很大；
- 压边；
- 跨区域；
- 非常规换行；
- 拉伸；
- 压缩；
- 错位；
- 描边；
- 路径化；
- 与图像或色块互动。

## 7.2 字体资源

优先：

- 微软雅黑：正文和关键事实；
- 得意黑：主标题、关键词；
- 霞鹜文楷：温暖、文化、节庆类辅助文字；
- Noto Sans / Serif：仅当前环境已有时使用。

## 7.3 不喜欢

不喜欢：

- 所有内容都用同一默认字体；
- 艺术化背景里突然出现未经设计的系统字体；
- 标题只是普通粗体放在最上方。

---

# 8. Component Integrity / 组件完整性偏好

这是 V1.0 新增的重要长期偏好。

一个视觉组件应尽量保持统一视觉语言。

例如一个气泡包含：

- 边框；
- 底色；
- 图标；
- 小标题；
- 正文。

如果小标题需要精确：

应优先把整个气泡作为统一精确组件设计，而不是：

- 外框由生成式图像完成；
- 里面突然叠一个默认微软雅黑标题。

## 8.1 不接受的割裂

避免：

- 生成式手绘边框 + 裸系统字体；
- 艺术化标签 + 普通 Word 式正文；
- 视觉主标题很有设计感，但所有辅助模块完全像 Office 文档；
- 一半是生成式艺术海报，一半是规整 PDF 排版。

## 8.2 喜欢的融合方式

喜欢：

- 同一组件内字体、边框、图标、颜色一起设计；
- 精确文本也融入整体视觉；
- 关键事实准确，但不显得“另贴上去”；
- 生成式视觉和精确排版共同服务同一个设计系统。

---

# 9. 文本艺术化偏好

## 9.1 可以艺术化

适合艺术化：

- 主标题；
- 副标题；
- slogan；
- 视觉关键词；
- 极短标签。

## 9.2 必须精确

优先精确排版：

- 电话；
- 时间；
- 日期；
- 地址；
- 机构；
- 报名方式；
- 二维码说明；
- 网址。

## 9.3 中间类型

活动亮点、服务项目、模块标题等：

根据组件决定。

若属于图形标签 / 气泡 / 卡片：

应整体设计，不要只叠一层普通系统字体。

---

# 10. 场景参考偏好

`references/scenarios/` 用来让不同服务场景有不同视觉语气。

喜欢：

- 应急服务和儿童活动明显不同；
- 健康义诊和社区音乐活动明显不同；
- 同样符合用户审美，但不是同一模板换颜色。

不喜欢：

- 场景分类只改变颜色；
- 所有服务类别仍然使用同一版式；
- 把场景参考理解成固定模板。

---

# 11. Style 参考池偏好

`references/style/` 建议保留 4–5 张真正喜欢的海报。

这些图可以风格混合，不需要分类。

Agent 应提炼：

- 共通视觉倾向；
- 用户喜欢的大胆程度；
- 色彩活跃度；
- 标题尺度；
- 图文关系；
- 背景处理；
- 图形元素；
- 留白和节奏。

不应：

- 一张参考对应一个方案直接模仿；
- 把多张参考平均成保守风格；
- 复制具体独特插画或完整构图。

---

# 12. Anti-Cardification

默认避免：

- 多个等宽矩形卡片；
- 顶部标题栏；
- 中部图片区；
- 底部大块信息栏；
- 每条信息一个框；
- 过度规整的栅格。

可以使用容器，但必须有设计理由。

优先：

- 非矩形色块；
- 圆形标签；
- 星型；
- 路径；
- 箭头；
- 悬浮信息；
- 贴边；
- 跨层；
- 图文重叠；
- 密度变化。

---

# 13. Gate 01 配色选择原则

长期偏好不替用户决定最终配色。

在 Gate 01.2 中：

Agent 应根据当前任务动态提出 3–4 个配色方向。

用户选择后：

必须以该选择为正式依据。

如用户选择“由 Agent 决定”：

再综合：

- 场景分类；
- style；
- 图片；
- visual-preferences

生成最终色板。

---

# 14. 最终判断标准

更符合偏好的结果通常具有：

- 第一眼有记忆点；
- 构图先成立；
- 色彩有性格；
- 背景真正参与设计；
- 标题具有图形性；
- 信息有主次；
- 关键事实准确；
- 精确文字没有破坏整体视觉；
- 组件之间属于同一视觉系统；
- 不看文字也能看出海报的结构和节奏。

最不喜欢的结果：

- 很安全；
- 很工整；
- 信息很全；
- 但像公告页、PPT 或 PDF 说明页。
