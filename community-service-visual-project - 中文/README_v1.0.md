# README_v1.0.md

# Community Service Visual Design Skill — V1.0

## 1. V1.0 是什么

V1.0 是本项目第一次架构级升级。

此前 v0.x 主要解决：

- Human Gate；
- Brief / raw-task；
- 场景图适配；
- 主题语义元素；
- 低保真方向图；
- 配色；
- 字体；
- 反卡片化；
- 无图 Graphic Poster Mode。

V1.0 在这些基础上进一步解决“普通用户如何更轻松地使用 Skill”和“生成式视觉如何与精确文字融合”的问题。

---

# 2. 最重要的变化

## 2.1 不再要求用户维护输入文件夹

默认从对话直接开始。

例如用户只需要说：

“帮我做一个社区旧物交换日海报，周日下午，中英文，4:5。”

Skill 会自动进入 Gate 01。

用户不再必须：

- 创建 raw-task；
- 创建 brief；
- 把图片预先复制到固定目录。

这些都变成可选高级用法。

---

## 2.2 Gate 01 改成分阶段动态问卷

Gate 01 现在包括：

### Gate 01.1A
基础事实问卷。

### Gate 01.1B
中英文案生成与确认。

### Gate 01.2
场景图、配色、信息密度和视觉策略确认。

用户不需要一次回答全部问题。

Skill 会根据前一步答案动态决定下一步显示什么。

---

# 3. 可点击问卷机制

V1.0 明确优先使用可点击问卷。

优先顺序：

1. 当前运行环境原生的可点击选择控件；
2. 本地轻量 HTML 表单；
3. 结构化文本问卷作为最后 fallback。

如果当前环境不支持真正的可点击控件：

不得假装有按钮。

应明确退回兼容方式。

---

# 4. Gate 01.1A 收集什么

只收集基础事实：

- 活动 / 服务名称；
- 目标人群；
- 时间；
- 地点；
- 机构；
- 联系方式；
- 参与 / 报名方式；
- 输出语言；
- 尺寸；
- 是否准备上传场景图。

已经知道的信息不再问。

这一阶段不问：

- 配色；
- 图片是否风格化；
- 图片是否适合任务；
- 图片要不要压暗；
- 拼贴方式；
- 视觉路线。

这些放到 Gate 01.2。

---

# 5. Gate 01.1B：文案确认

基础事实足够后，Skill 自动生成：

- 中文海报文案；
- 英文海报文案（如需要）。

然后让用户选择：

- 全部确认；
- 中文修改；
- 英文修改；
- 两版精简；
- 两版更有传播感；
- 用户自行修改。

文案确认完成前：

不得进入视觉设计。

---

# 6. Gate 01.2：图片与视觉选择

## 0 张图片

默认：

Graphic Poster Mode。

使用：

- 色块；
- 图标；
- 圆形；
- 星型；
- 箭头；
- 简化人物；
- 简化建筑；
- 大标题。

## 1 张图片

上传后再判断：

- 是否符合任务；
- 是否适合作背景；
- 是否需要调色；
- 是否允许裁切；
- 是否允许风格化；
- 是否允许日夜 / 天气改变。

## 多张图片

上传后：

- Agent 推荐主图；
- 推荐辅助图；
- 用户选择是否拼贴、胶片、多窗格、Hero + Supporting 等形式。

---

# 7. 配色怎么选

V1.0 不在 visual-preferences 里固定具体颜色。

配色在 Gate 01.2 由 Agent 根据当前任务动态生成 3–4 个选项。

用户直接选择。

这样不同任务可以真正变化，而不是一直使用同一组蓝黄绿。

---

# 8. 场景参考库

推荐结构：

```text
skill/references/scenarios/
├─ 健康义诊/
├─ 老年关怀/
├─ 儿童教育/
├─ 政策宣传/
├─ 社区活动/
├─ 环境保护/
├─ 志愿服务/
├─ 应急服务/
└─ 通用/
```

每类放少量参考图即可。

它们不是最终素材。

用途是：

- 改变不同服务场景的排版逻辑；
- 改变信息语气；
- 改变图形表达；
- 避免每个任务都长得一样。

# 9. style 文件夹

继续保留：

`skill/references/style/`

建议 4–5 张。

不需要分类。

不需要特殊命名。

Agent 将其视为整体审美样本池。

---

# 11. Gate 02

Gate 02 必须输出 3 张真正可比较的方向图。

不再只给文字方向。

三种方向根据图片数量动态变化：

- 0 图：Typography / Graphic / Editorial / Illustration；
- 1 图：Hero / Hybrid / Image + Type；
- 多图：Hero + Supporting / Collage / Multi-window。

用户选择后才进入正式稿。

---

# 12. V1.0 的图像与文字融合方式

V1.0 不再采用简单的：

“生成式图片一半 + PDF 文字一半”。

而采用：

**组件级混合渲染。**

关键原则：

如果某个信息块需要精确文字：

尽量把整个信息块作为统一组件设计。

不要出现：

- 艺术气泡；
- 里面突然一行默认微软雅黑；
- 视觉上像后贴的文字。

---

# 13. 哪些文字必须精确

必须精确：

- 电话；
- 时间；
- 日期；
- 地点；
- 地址；
- 机构；
- 报名方式；
- 二维码说明；
- 网址。

可以更艺术化：

- 主标题；
- 副标题；
- slogan；
- 短关键词。

其他信息根据组件决定。

---

# 14. PDF 在 V1.0 中的角色

PDF 不再是默认视觉生成阶段。

只有在：

- 用户需要打印；
- 需要矢量版；
- 需要精确版式存档；

时使用。

如果任务要求 PNG：

最终必须实际输出 PNG。

---

# 15. 用户的最短启动方式

推荐直接输入：

“帮我做一个社区宠物友好日海报，周六下午，面向居民家庭，中英文，4:5，按 Skill 执行。”

然后 Skill 自动进入 Gate 01。

无需额外说明：

- 去哪里找 brief；
- 去哪里找 raw-task；
- 去哪里找图片。

# 17. 一句话理解 V1.0

V1.0 不再要求用户“先学会项目文件结构，再使用 Skill”。

而是：

**一句话发起任务 → 分阶段可点击问卷 → 文案确认 → 图片与配色确认 → 三个可视化方向 → 组件级图文融合 → 最终 PNG。**
